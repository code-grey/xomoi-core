How It Handles So Much, With So Little?

Achieving 40,000+ msgs/sec on an outdated dual-core CPU isn't magic. It requires completely rethinking how memory is allocated and tearing apart standard libraries.

1. O(1) Pointer-Injection Routing

Standard MQTT brokers waste massive CPU cycles parsing topic wildcards (+, #) for every incoming payload. We surgically bypassed Mochi-MQTT's standard router for telemetry streams. Instead, Xomoi resolves the WebSockets subscriber channel exactly once, and injects a direct memory pointer. Routing complexity drops from O(N) to O(1), entirely bypassing the Garbage Collector.

2. CGO Context-Switch Annihilation

When Go writes to SQLite, it must cross the CGO boundary into C-land. Executing 5,000 separate SQL INSERTS triggers 5,000 expensive CGO context switches, pinning the CPU at 100%. We bypassed the standard Go ExecContext by using strings.Builder to manually construct massive 1,000-row SQL bulk strings in RAM. This slashed CGO context switches by over 99%.

3. The 100k Ring-Buffer Absorber

Edge IoT devices write to cheap SD cards that frequently freeze for 2-3 seconds during wear-leveling. If a broker blocks on I/O, it applies TCP Zero-Window pressure, causing thousands of drones to drop connection. Xomoi uses a custom Go Ring-Buffer that queues up to 100,000 packets in just 17MB of RAM, acting as an invincible shock absorber during disk freezes.

Where Xomoi Dominates

AWS IoT Core vs A 10-Year-Old CPU: AWS IoT Core enforces a hard default ceiling of 500 connections per second. Our tests prove that Xomoi-Core on a dual-core Intel Pentium handles a 5,000 connection Thundering Herd spike effortlessly, maintaining a GC pause latency of just 3.2 milliseconds.

5 Docker Containers vs 1 Static Binary: Traditional stacks (Mosquitto + InfluxDB + Redis + Nginx + Backend) require 5 Docker containers. The Docker network bridge (veth) and daemon overhead alone consume more RAM (~200MB+) than the entire Xomoi executable. Xomoi eliminates moving parts that break in remote fields.

TCP Network Hopping vs Shared Memory: Standard architectures pipe payloads over TCP loops between the broker, backend, and TSDB, burning CPU on kernel context switches. Xomoi uses Go's zero-allocation channels to pass memory pointers natively from the broker to the SQLite Flusher at O(1) time complexity.

The Hardware Arbitrage

Transform E-Waste into Profit: Because Xomoi requires just ~17MB of RAM and routes 40,000+ msgs/sec on obsolete silicon, investors don't need to fund expensive $1,000 Kubernetes Edge Gateways. You can literally flash Xomoi onto repurposed $15 OpenWrt routers, Intel NUCs, or old Raspberry Pis and deploy enterprise-grade, offline-first IoT infrastructure.

Zero Cloud CAPEX: Skip the AWS/GCP per-message billing entirely. By pushing the intelligence down to decentralized, air-gapped bare-metal nodes, you achieve infinite local scaling with absolute zero monthly cloud costs.

Where Xomoi Fails

Massive Cloud Data Centers: Xomoi is strictly an edge-first, offline-first node. If you are building a central cloud cluster handling millions of concurrent vehicles globally, use EMQX or Kafka.

Independent Microservice Scaling: If your architecture relies on independently scaling the database layer from the broker layer across multiple servers, Xomoi's hyper-converged monolith approach will fight you.
